# Project Summary & Chat History

## 1. Project Overview & Goal
Automate trade execution on **GooeyTrade** (web-based trading interface) based on signals generated by a custom Pine Script indicator running on **TradingView** (XAUUSD / Gold 5m timeframe). The automation runs autonomously both locally and via scheduled GitHub Actions workflows.

---

## 2. Architecture & Components

### TradingView Scraper (`tv_scraper.py`)
- **Canvas / Drawing Challenge**: TradingView renders custom Pine Script indicators (lines, labels, tables) directly onto an HTML5 Canvas, making them inaccessible via standard DOM text queries.
- **Solution — Screenshot + Tesseract OCR**:
  - Playwright loads the TradingView chart with saved user session (`tv_session.json`).
  - Takes a 1920x1080 screenshot of the chart after letting Pine Script calculate and render.
  - Crops the top-right corner where the Pine Script indicator outputs its table:
    - Bounding Box: `TABLE_CROP = (1635, 42, 1815, 160)`.
  - Runs **Tesseract OCR** using `--psm 6` (single uniform block of text).
  - Extracts 4 rows:
    - `BUY <price>` or `SELL <price>`
    - `SL <stop_loss_price>`
    - `TP <take_profit_price>`
    - `Status FRESH` or `Status OLD`
  - Fallbacks: Retains legacy DOM parsing as backup.

### Bot Execution (`run.py`)
- **Phase A (Entry)**:
  - Scrapes TradingView via `tv_scraper.py`.
  - Detects signal direction and entry price.
  - Checks freshness: compares the signal entry price with live GooeyTrade market price.
  - If fresh, clicks Buy/Sell order button on GooeyTrade.
- **Phase B (SL/TP)**:
  - Extracts Stop Loss and Take Profit levels from the signal.
  - Modifies open position on GooeyTrade to apply the target SL/TP prices.
- **State Management**:
  - Tracks placed trades in `bot_state.json` to prevent duplicate orders for the same signal.

## 4. Signal Freshness & Age Detection

### Question: Can OCR know how long ago a signal was detected?

#### How it works currently (Price Distance Check):
- Without any timestamp on screen, OCR only reads the static numbers.
- `run.py` currently checks freshness by comparing:
  $$\text{distance\_pct} = \frac{|\text{entry\_price} - \text{current\_price}|}{\text{current\_price}} \times 100$$
- If the price moved more than 0.5% away, the bot assumes the signal is stale and rejects it.

#### How OCR CAN directly know the exact age:
If you add a **4th row** to your Pine Script table displaying either:
1. **Bars Ago**: Number of bars since the signal triggered (e.g., `BARS 0`, `BARS 1`, `BARS 2`).
2. **Minutes Ago**: Time elapsed since signal (e.g., `AGE 3m`).
3. **Timestamp**: Bar close time (e.g., `TIME 14:25`).

**Pine Script snippet example**:
```pinescript
var int signal_time = 0
if buy_condition or sell_condition
    signal_time := time

// In table rendering:
int minutes_ago = math.round((timenow - signal_time) / 60000)
table.cell(sig_table, 0, 3, "AGE " + str.tostring(minutes_ago) + "m", bgcolor=color.black, text_color=color.white)
```

**OCR can then read**:
```text
BUY 4340.28
SL 4167.58
TP 4858.37
AGE 2m
```
And python will parse:
```python
if signal.get("age_minutes", 999) > 5:
    print("Signal is older than 5 minutes — skipping")
```

## 5. What Was Actually Implemented (FRESH/OLD Status)

Instead of `AGE Xm`, the user chose a simpler approach — a binary `FRESH` / `OLD` status row:

**Pine Script now outputs 4 rows:**
```text
BUY 4366.28
SL 4358.11
TP 4390.8
Status OLD
```

**OCR parses all 4 rows:**
```python
signal = {
    "direction": "buy",
    "entry_price": 4366.28,
    "sl": 4358.11,
    "tp": 4390.8,
    "status": "old"  # or "fresh"
}
```

**Bot behavior:**
- `FRESH` → bot proceeds to check price and place trade
- `OLD` → bot skips with message: `Signal status: OLD (>120s) — skipping`

**Verified working:**
```
[Phase A] Entry signal: BUY @ 4366.28
[Phase A] Signal status: OLD (>120s) — skipping
No actionable signals from TradingView this run.
```
